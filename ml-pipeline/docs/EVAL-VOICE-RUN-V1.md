# EVAL-VOICE-RUN-V1 execution boundary

This is Adeel's offline ML evaluation workstream. It implements the execution policy already
frozen in [EVAL-VOICE-V1](EVAL-VOICE-V1.md), not a protocol amendment or model-selection ADR.
The corpus identity remains `FLEURS-VOICE-V1` and its manifest SHA-256 remains
`e2efd78d0af8fe8ecc2c6483ab7db0ff9dba6763fd148be58bbc6c4fd05499e4`.

## Integrity and execution

The existing full corpus verifier runs before either model is created and again before final
evidence is installed. It checks all 200 identities/audio/reference/language/lineage records,
409 indexed files plus the manifest, external registries and frozen normalization/scoring code.
No benchmark file is repaired, rewritten or regenerated by the runner.

Pinned checkpoints are acquired separately into the ignored workspace Hugging Face cache.
Official pinned-revision metadata supplies whole-checkpoint SHA-256 and small-file Git blob
identities. Bounded range acquisition validates exact ranges and whole-file checksums before
installing weights; no different model, unsafe pickle weights or revision fallback is used.
The dataset's 1 GiB source-object bound is not relaxed to accommodate model checkpoints.
Acquisition failures are operational dependencies, not decoder outputs or model-quality scores.

Each model runs in its own fresh process on CPU/float32 through the existing adapters.
Base loading and MMS language adapter changes are measured separately. For each language,
the first sample under the frozen seeded selection key receives exactly one unscored warmup;
every sample then receives exactly one scored call in lexical `sample_id` order.
Languages use the existing declared
`en`, `ur`, `sd`, `ps` mappings. Greedy Whisper/CTC MMS decoding is unchanged.
There are no inference retries, favorable-output selection or transcript corrections.

Raw decoder output is retained even when the unchanged transcript contract rejects empty
output. Invalid UTF-8 surrogate output is retained as exact codepoint evidence, never rewritten
into a valid hypothesis. Valid outputs use the existing normalized transcript and checksum.
Per-sample crash checkpoints are evidence only: they are never consumed for automatic resume
or rerunning selected samples. Existing final results/checkpoints block another `run`.
Use `verify` to validate completed evidence without any new model call.

If base or language adapter loading fails, affected samples retain explicit typed failures,
null decoder/transcript/timing fields and full-reference-deletion scoring. Loading is not
silently retried for each sample. No warm latency is fabricated for an unattempted inference.
This documents an unavailable execution path, not measured neural recognition quality.

## Scoring and timing

Primary scoring calls the existing frozen `scoring_text` view and existing Levenshtein helper:
NFC/control/whitespace normalization, casefold, Unicode punctuation-to-space, then collapse.
Both reference and hypothesis use the same view. Failed/empty outputs score as full reference
deletions without publishing a fabricated transcript. WER/CER are not clamped.

Report micro WER/CER separately for each language and the preregistered equal-language macro
average of those four rates. No pooled denominator, new weighting or success-only score is used.
No confidence intervals are added in this gate; the preregistered bootstrap is not required
unless intervals are reported. No winner or production dependency is selected.

Warm timing summaries use all attempted scored calls, including failures, excluding warmups
and separately observed base/adapter loads. Mean/median/p95 STT milliseconds and real-time
factor are reported per language/model. Missing timings remain null, never zero. Failure timing
measures the adapter call itself, not reference scoring or error serialization.
Cold loading includes fresh-process library initialization when performed by the existing
adapter; it is observational, separate from warm latency, not an SLO test.

## Evidence and commands

```powershell
python scripts/prepare_voice_evaluation.py verify
python scripts/acquire_voice_models_v1.py --allow-download --workers 8
python scripts/run_voice_evaluation.py run
python scripts/run_voice_evaluation.py verify
```

The run is offline; it requires the verified weights to be cached first and never downloads
inside a timed or cold-load model call. Both acquisition and execution use the workspace
`.cache/voice/huggingface` cache rather than storing credentials or writing outside the checkout.

Output is under `artifacts/eval_voice_run_v1/`: pinned asset acquisition evidence, one result
file per model, scored-call checkpoints and a checksum-anchored comparative manifest. Records
include sample/audio/language/model/revision, exact decoder output, normalized transcript and
checksum, typed status/failure, frozen scoring counts/rates and separate timing observations.
Model result files also retain fresh base/adapter loads, unscored warmups, CPU/runtime/dependency
information and implementation-file checksums. Semantic result hashes exclude timing; the
artifact checksum anchors the actual measured operational evidence as well.

Verification recomputes transcript checksums, per-sample scores, language summaries, semantic
hashes, model/protocol/corpus identities and warmup structure. It checks the comparative manifest
against current complete result bytes. Byte-identical neural inference across hardware is not
claimed. The actual execution outcome is documented in `reports/eval_voice_run_v1.md`.

The existing opt-in adapter smoke tests use a separate English source-only input selected
before any model output (`smoke-input.json` / `smoke-selection.json`). Those two unscored
regression calls do not replace primary transcripts or rerun the 200-sample evaluation.
Observed elapsed-time stalls remain in all latency summaries; the report explicitly limits
performance interpretation rather than filtering outliers or rerunning samples.

MMS remains CC-BY-NC-4.0 research comparison only. Published read-script references, locale
coverage, FLEURS training-domain exposure and lack of commerce-domain validation remain as
preregistered. No text retrieval, labeling, Search, FTS, API, voice-to-search, Commerce,
frontend, authentication or deployment behavior belongs to this runner. Stop after evidence.
